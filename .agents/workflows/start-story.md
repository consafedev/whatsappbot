# /start-story

1. Verify git/STATUS/current story.
2. Load project skill and normative docs.
3. Inspect existing implementation.
4. Write a short requirement/evidence plan.
5. If architecture conflict exists, STOP.
6. Implement only the story.
7. Add tests first or alongside the invariant.
8. Run story tests and relevant regressions.
9. Review diff for scope/security/tenant/provider leaks.
10. Update docs.
11. Commit.
12. Report evidence and STOP before next story.

# E14 Agenda Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. The user authorizes autonomous execution and per-story commit/push; do not pause for approval.

**Goal:** Complete the active Agenda epic S04–S10 with evidence per story.
**Architecture:** Existing tenant managers + PostgreSQL audit/outbox, guarded Nest
API, Next shell, rules and WorkflowOrchestrator. Resource-level transactional
locking protects booking; external messaging uses existing outbound persistence.
**Tech Stack:** TypeScript, pnpm, Prisma/PostgreSQL, Nest, Next, Vitest/Biome.
**Spec:** docs/superpowers/specs/2026-10-25-e14-agenda-design.md

## Global Constraints

- One epic E14; no real Baileys/Messenger adapter installation here.
- Tenant authority derives from authenticated context; every owned query scoped.
- Existing API envelopes, permissions and module keys; PostgreSQL is authority.
- Never print/copy/commit .env; load it with Node process.loadEnvFile for checks.
- Tests first, review and correct every story before starting the next.
- Per-story STATUS/CHANGELOG/backlog/MANIFEST and coordination record updates.
- Parent controller owns final documentation, checks, commits and push.

## Review Focus

- Invalid or ambiguous temporal input: offset required; DST and half-open ranges.
- Concurrent overlapping capacity: resource lock and atomic rollback.
- Cross-tenant association and retry payload tampering: DB and API negatives.
- Stale reminders after rebook/cancel: reread current appointment before send.
- Duplicate inbound/idempotency and human takeover: one booking, no bot takeover.

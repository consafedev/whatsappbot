# E13-S05 Scheduled Task Run History Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Persist tenant-safe scheduled-task run outcomes and durations, expose paginated read APIs, and add an accessible per-task history panel.

**Architecture:** PostgreSQL stores immutable terminal runs; the worker and stale-task reconciler append outcomes through the database boundary. Nest endpoints read through tenant-scoped manager methods, and the existing Next.js console consumes them with `scheduling.read` access.

**Tech Stack:** TypeScript 6, Prisma 7.9.1, PostgreSQL 18, NestJS 11, BullMQ, Next.js 16, Vitest, Biome, pnpm.

**Spec:** `docs/superpowers/specs/2026-10-02-e13-s05-scheduled-task-run-history-design.md`

## Global Constraints

- PostgreSQL is the source of truth; BullMQ payload stays `{ tenantId, taskId }`.
- Every `scheduledTaskRun` query includes authenticated `tenantId`.
- API/UI reads require `module.scheduling` and `scheduling.read`.
- Run history is append-only; no update/delete API or manager methods.
- Use UUIDv7 and `TIMESTAMPTZ(3)` conventions.
- Do not change task create/cancel/retry contracts or add dependencies.
- `TIMEOUT` means E13-S03 stale recovery observed `PROCESSING` beyond threshold; it may be timeout or worker crash.
- Migration name: `20260912180000_add_scheduled_task_runs_foundation`.

## Review Focus

- Foreign task/run IDs and spoofed tenant inputs disclose no cross-tenant rows (DB/API A/B tests).
- Stale recovery racing a resumed worker creates one immutable row per claimed attempt (DB/worker duplicate tests).
- Millisecond timestamps and retries do not overwrite an earlier attempt (DB tests cover same attempt duplicate and later retry).
- Raw exceptions, provider results, task payloads, and secrets never enter `errorMessage`/`metadata` (worker tests assert stable codes).
- Invalid pagination, empty history, API errors, and out-of-range pages have stable API/UI states (API/web tests).
